# Composite command resources — candidate scope

The composite file scope also enrolls `codec select` and
`codec encode-selected`. Candidate realizations, exact inverse checks, the
rooted selection record, and selected replay share the same bounded scratch and
publication model. This enrollment is not a RAM cap, future-workload prediction,
or global compression optimum claim.

The existing `fold build/prefix/extract/restore-rich`, five assembly mutation
commands, `select`, `encode-selected`, and `archive select` accept
`--max-scratch-bytes` (default 4 GiB). Their snapshots, native database capacity,
nested compilation/decoding, candidate trials and staged output share one owner.
The API is `semcrys.application.run(OPERATION, source, output, **options)`;
ARCHIVE_SELECT uses `source=None` and explicit `sources`.

Every call compiles a rooted resource Instance Constitution before allocating
private work. CLI publication separately compiles its matching operation and
counts the output, exact receipt, replacement backups and bounded recovery journal.
The aggregate is the maximum of sequential realization/publication phases, not
their sum. Progress is stderr; results and optional receipts expose both scopes.

This is a logical-file-length/native-capacity limit, not a RAM limit or guarantee
against physical disk exhaustion. Directory-producing `fold compact`,
`batch-encode`, and `archive encode-selected` are not enrolled by this contract.
The existing source/legend/front/record ceilings still apply independently.

Fold calibration now ranks through an explicitly reserved main-database index:
frequency descending, first occurrence ascending. No new ranking heuristic or
selection objective is introduced. Decoder-visible formats, source identities,
legend order, and cold/warm dependency accounting remain unchanged. Rule packs,
parent chains, calibration inputs, library/selection manifests, projection
provenance and archive dependencies are protected before replacing the target
with a private stage. No automatic shared-legend adoption or canonical mutation.

This integration is candidate evidence, not a release or security claim. It does
not remove directory publication, independent platform/ABI acceptance, combined
maxima, physical failure, concurrency, or whole-process memory qualification gaps.
