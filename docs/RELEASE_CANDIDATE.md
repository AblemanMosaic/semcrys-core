# SemCrys v0.1.0 release status

Replacement publication authorized: 2026-11-05.

This replacement package is **authorized for GitHub publication by the project
owner**. The recorded decision is bound by `PUBLICATION_DECISION.json`.
Publication does not create canonical semantic identity,
production admission, formal external certification, or publisher
authentication.

## Established locally

- The `.crys` 0.2, binary `.leg` 0.2, and `.gly` 0.1 formats remain rooted and
  fail closed on unsupported critical configuration.
- Standard archive v0.3 adds profit-governed local/cross-document composition,
  exact member offsets, non-overlapping observability, and verified composition
  cache reuse while retaining v0.2 read compatibility.
- All CLI leaf commands compile from the same parser used by the
  machine-readable capability surface; release-scope effects correspond exactly.
- All 79 legacy migration items have rooted explicit dispositions.
- Lite security projections now separate frequency balancing, keyed position
  projection, and count/size padding. The security court includes
  sample-adjusted alias correlation plus bounded bigram/trigram shuffled-null
  gates; no protocol proof or independent cryptanalysis is claimed.
- Applicable predecessor and successor source regression suites pass.
- The wheel and zipapp are built twice offline and must be byte-identical.
- The standalone Windows application is built twice, its embedded standard
  library zip is canonicalized, and the complete distributions must be
  byte-identical. See `evidence/WINDOWS-STANDALONE-COURT.json`.
- The standalone Linux x86-64 application is separately built twice on Linux,
  carries an exact glibc floor and bundled-runtime inventory, and must pass its
  own executable replay court. See `evidence/LINUX-STANDALONE-COURT.json`.
- Both standalones carry third-party custody notices and rooted runtime binary
  inventories. Source/zipapp standard-library dependency claims are not reused
  as claims that frozen distributions contain no third-party runtime code.
- The zipapp and an isolated wheel installation must pass `verify-self`,
  capability/format/workbench correspondence, exact round trips, typed refusal,
  and package-inventory checks before a distribution receipt can pass.

## Not established

No global compression optimum, unseen-workload prediction, arbitrary option
product, universal RSS/scale bound, power-loss atomicity, cross-OS/network lock
interoperability, or cryptographic confidentiality is claimed. No private
legend, model, dataset, or network service is bundled. Standalone applications
do bundle an inventoried Python runtime; source, wheel, and zipapp profiles do
not.

Independent reproduction and public publication remain separate evidence
dimensions. The supplied reviewer court reproduced the bounded release claims;
exact artifact hashes establish correspondence, not publisher identity when an
attacker can replace both payload and manifest.
